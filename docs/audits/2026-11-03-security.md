# Tang OS security audit — November 3, 2026

## Scope and outcome

Reviewed the current local source, production dependency graph, server entry points,
client rendering and terminal dispatch, public assets, browser policies, and common
secret patterns in the source, built client, and Git history. Independently reviewed
server trust boundaries and reproduced findings locally. Read the deployed homepage's
response headers without sending email, credentials, attack traffic, or load tests.

Known critical dependency advisories were found and patched locally. Two medium
resource-abuse paths were reproduced and remediated. No additional critical or high
application exploit was identified in the reviewed source. This is a bounded audit;
it does not establish the absence of all vulnerabilities or evidence of compromise.

The initial live inspection preceded these changes. Its exact running dependency
version and Vercel account configuration were not verified. Deployment verification
is recorded separately in the final handoff.

## Findings and remediation

| Finding | Evidence | Local change |
| --- | --- | --- |
| Critical dependency advisories | The lockfile installed Next.js 16.4.0. npm audit reported critical image-optimization and typed-array cache advisories and a high Server Actions DoS advisory. Prerequisites vary; exploitation of this site was not demonstrated. | Updated Next.js and its lockfile to 16.4.5. Both full and production-only npm audits report zero known vulnerabilities. |
| Medium: download email abuse | The optional POST accepted cross-origin text/plain JSON and sent once per request when its provider key was set. Mocked outbound calls demonstrated this without real email. Body size was unbounded. | Require same-origin JSON using the public Host header, validate allowlisted files, read at most 1,024 bytes with a two-second deadline, and bound provider calls to five seconds. Aggregate notifications by file and fixed six-hour window using a deterministic Resend idempotency key/payload. Warm instances also suppress duplicate calls. Remove full referrer and user-agent collection. |
| Medium: unnecessary image transformation | No component uses next/image. Locally, fragment variants of one image produced independent optimizer cache misses with identical output. Vercel continued serving its native optimizer after the initial app-only setting. | Disable the local optimizer with images.unoptimized and explicitly deny all local/remote optimization sources in both next.config.ts and Vercel's native image configuration. Retain normal static image URLs. |
| Browser hardening | Live homepage had HSTS, but no observed CSP, frame protection, nosniff, explicit referrer policy, or permissions policy. Missing headers alone did not demonstrate an exploit. | Add resource CSP, frame-ancestors none/X-Frame-Options DENY, nosniff, strict-origin referrers, feature restrictions, and HSTS. Remove X-Powered-By. |

## Important boundaries

- Resend retains idempotency keys for 24 hours. The fixed six-hour key caps accepted
  email sends to one per file per bucket across instances. This is not a global limit
  on incoming HTTP requests, function invocations, or failed provider API attempts.
- Notification frequency intentionally changes: downloads still work normally, while
  notification emails summarize activity instead of sending for every download.
- CSP permits inline Next.js bootstrap scripts and inline styles to preserve static
  rendering and draggable windows. It is not a strict nonce-based XSS policy.
  WebAssembly compilation is permitted for the self-hosted chess engine; general
  JavaScript eval is allowed only in development.
- React renders visitor terminal input as text through a fixed command switch; it
  does not run a system shell. JSON-LD escapes `<`; other inline scripts are constant.
- Common secret patterns had no matches in current app/public/client output or Git
  history. This does not cover all possible credentials or secrets outside this repo.
- This application report does not publish private account configuration. The subsequent
  Vercel and registrar review is recorded separately outside the public repository;
  application release validation continues in `2026-11-03-chess-polish.md`.
- After deployment, verify live headers, the disabled optimizer, chess worker loading,
  normal downloads, and rejected invalid/cross-origin requests. Do not send a test
  notification with a real key unless explicitly authorized.

## Verification record

Verified locally against the production build:

- `npm run verify`: TypeScript and production build passed; 183/183 crawlability checks passed.
- `npx playwright test`: 49/49 passed, including all chess, security, mobile, portfolio,
  and simulator regressions. Real engine replies were tested at every preset, including
  phone touch input; promotion, undo, cancellation, retry, and narrow/landscape layouts passed.
- `npm audit` and `npm audit --omit=dev`: zero known vulnerabilities.
- Independent chess and server-security reviews completed; material findings were fixed
  and covered with regression tests, including same-origin handling behind proxy aliases.
- Desktop and phone chess screenshots were rendered and inspected.
- The original mobile gesture tests also failed against an untouched production baseline.
  Event tracing showed CDP swipes suppressing a subsequent synthetic click. Window controls
  now run before dock swipes, swipes stop at scroll boundaries, and every original target-size
  and window-geometry assertion remains in place. No shared window behavior was changed.

Tests use mocked email delivery; integration requests use invalid file IDs so they cannot send email.
